## Verification Technologies

|Technology / Method|Status|Purpose / Why Consider It?|Team Experience|Strengths|Limitations / Risks|Notes / Priority|
|---|---|---|---|---|---|---|
|**UVM / SystemVerilog**|Established|Full-featured, transaction-based RTL verification methodology. Suitable for complex reusable verification environments.|Albert, Rafa|• Industry-standard methodology• Strong object-oriented programming support• Transaction-based scoreboards and checking• Register models and constrained-random verification• DPI-C allows integration with C/C++ and external software• Good simulator debugging and reporting capabilities• Mature ecosystem and reusable components|• Simulator license may be required• Initial environment setup can be time-consuming• SystemVerilog is less flexible than general-purpose software languages• Learning curve for UVM architecture|Consider **UVMF** or reusable verification frameworks to reduce environment setup time. **High priority for complex RTL verification.**|
|**cocotb**|In progress / Under evaluation|Python-based verification framework that controls simulators and enables software-style testbench development.|Rafa: analysis onlyAlbert: analysis only|• Python ecosystem and libraries• Fast development and prototyping• Reuse Python data generation and reference models• Object-oriented programming• Potentially easier onboarding for software-oriented engineers• Can work with multiple simulators|• Concurrency model needs evaluation• Simulation performance may be a concern• Python/SV integration and debugging need validation• Team learning required|Good candidate for evaluation. Can potentially be combined with **pytest** for test organization. **Medium–High priority.**|
|**OSVVM**|In progress / Under evaluation|Verification methodology and library primarily targeted at VHDL-based verification.|Not specified|• Native VHDL support• Useful for VHDL-centric designs and teams• Avoids introducing another primary testbench language|• Smaller ecosystem compared with UVM/SV• Reporting/debugging features need evaluation• May not provide the same flexibility as Python-based environments|Best evaluated if the RTL and verification flow is strongly VHDL-based. **Medium priority.**|
|**pytest**|In progress / Under evaluation|Python test framework for organizing, executing, configuring, and reporting tests.|Rafa: hardware testing|• Excellent test organization and reporting• Fixtures simplify test configuration and setup• Large Python ecosystem• Reusable test infrastructure• Can support parameterized and regression tests|• Not an RTL verification methodology by itself• Requires integration with a simulator/testbench framework|Strong candidate as a **test execution and organization layer**, especially together with cocotb. **High priority as supporting infrastructure.**|
|**OneSpin / Formal Verification**|To be evaluated|Formal verification and property checking for proving design behavior rather than relying only on simulation.|Not specified|• Can exhaustively explore specific properties and corner cases• Effective for finding difficult bugs early• Complements simulation-based verification|• Requires formal expertise• Property and constraint development can take significant effort• Scalability depends on design complexity|Evaluate for critical blocks, protocols, safety properties, and areas where simulation coverage is insufficient. **Medium–High priority depending on project needs.**|

## Tooling and Supporting Technologies

|Tool|Status|Primary Use|Team Experience|Strengths|Limitations / Risks|Notes / Priority|
|---|---|---|---|---|---|---|
|**Verilator**|Option / Under evaluation|Open-source RTL simulation and lint-oriented development flow.|Not specified|• No commercial simulator license required• Fast simulation for supported designs• Good for CI and automated testing• Integrates well with software and open-source flows|• Not fully feature-compatible with commercial simulators• Partial language and feature support depending on the design• May not be robust enough as the only verification simulator|Strong candidate for **fast local testing and CI**, while retaining a commercial simulator for full verification. **Medium–High priority.**|

|**NVC**|To be evaluated|Open-source VHDL compiler and simulator.|Not specified|• Open-source• Lightweight VHDL simulation• Potentially useful for automation and CI|• Primarily focused on VHDL• Feature and ecosystem support may be more limited than commercial tools|Worth evaluating for VHDL-focused projects and automated testing. **Medium priority.**|
